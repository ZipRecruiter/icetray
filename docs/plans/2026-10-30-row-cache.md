# Row cache, one page cache, and the cache budget: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Key-value lookups read values from a row cache in memory ahead
of one page cache that every table shares, whose disk level Scans now
read, under one memory budget derived from the process's memory limit.

**Architecture:** A new `row_cache` module wraps quick_cache, keyed by
file path, row position, and the file's column leaf; `Generation::lookup`
consults it after the index and the delete check and before
`FileIndex::read_column`. The scan cache goes away: ordered tables read
the lookup `PageCache`, whose `get_span` learns to read the hybrid disk
level. `ServerConfig` loses `page_cache_bytes` and
`scan_page_cache_bytes` for `cache_bytes` and `row_cache_share`, resolved
against `memory::limit()` when the caches open.

**Tech Stack:** Rust, quick_cache (new), foyer 0.22.6 (existing), tokio,
serde, metrics.

**Spec:** `docs/rfd/026-row-cache.md`, `docs/rfd/027-one-page-cache.md`,
`docs/rfd/028-cache-budget.md`, with the 2026-10-30 updates to
`docs/rfd/025-ordered-rows.md` and `docs/rfd/011-configuration.md`.

## Global Constraints

- `CONTRIBUTING.md` and `AGENTS.md` apply in full. Read both first.
- cargo, clippy, and tests run through flox: `flox activate -- cargo ...`.
- Add quick_cache with `cargo add quick_cache` in `crates/icetray-core`,
  then move it to `[workspace.dependencies]` the way `foyer` is declared,
  keeping the version `cargo add` wrote. No version from memory.
- Never `#[allow(...)]`. `#[expect(dead_code, reason = "...")]` only for
  code a later task in this plan reads, removed in that task.
- No sleeps in tests. Concurrency tests synchronize on events.
- Comments state constraints; history goes in commit messages.
- Conventional Commits, no co-author or generated-by trailers, never
  bypass the pre-commit hook, never push.
- A user-visible change updates `docs/configuration.md` (settings and
  defaults), `docs/operating.md` (metrics, logs), and the guide for its
  reader in the same commit. Defaults are named constants in `config.rs`
  beside the setting.
- One concept per file: the row cache lives in
  `crates/icetray-core/src/row_cache.rs`.
- Defaults this plan fixes, each a named constant with a doc comment
  giving the reason:
  - `DEFAULT_CACHE_SHARE_OF_LIMIT: f64 = 0.5` (`config.rs`), the share of
    the memory limit `cache_bytes` defaults to.
  - `FALLBACK_CACHE_BYTES: u64 = 256 * 1024 * 1024` (`config.rs`), the
    budget when no limit can be read.
  - `DEFAULT_ROW_CACHE_SHARE: f64 = 0.9` (`config.rs`), from the trace
    (RFD 028).
  - `ROW_CACHE_MAX_VALUE_BYTES: usize = contract::VALUE_PAGE_BYTES`
    (`row_cache.rs`), above which a value is not cached.
  - `ROW_ENTRY_OVERHEAD_BYTES: u64 = 160` (`row_cache.rs`), quick_cache's
    per-entry cost above key and value, from the bake-off (about 120
    bytes at 100-byte rows once jemalloc's rounding is taken out).
- Gate at the batch: `cargo test -p icetray-core` (or the crate touched)
  per task; `dev/ci-checks.sh` and `cargo test --workspace` once at the
  end, read to completion.

## Review Focus

1. A cached value that is a slice of its page would keep the whole
   64 KiB page alive while being weighed at the value's length: the
   entry must own a copy (Task 3 pins it).
2. Two tables over the same files listing value columns in different
   orders must each read their own columns from shared entries, since
   the key is the file's leaf, not the layout position (Task 3).
3. A reload that adds an ordered table, or a `row_cache = false` table,
   to a server with row-cache tables and no disk level is refused whole,
   not applied with the thin split (Task 6).
4. Under `bloom`, a row-cache hit still reads its key page through the
   page cache, and a cold key page is still a GET counted against the
   fan-out (Task 3).
5. A derived budget on a host with no cgroup limit is a share of the
   host's memory, and one whose page share is below the minimum is
   refused naming the limit (Task 2).
